# Virus Sim 구조 설명 스타일 가이드

## 기본 원칙

설명은 생물학적 실체와 현재 3D 모델을 분리해 쓴다. source가 알려 주는 구조를 먼저 정확히 이름 붙이고, `modelRepresentation`에는 화면에 실제로 그려지는 절차 기하만 적는다. 모델의 club, shell, coil을 원자 구조나 실제 분자 배열처럼 설명하지 않는다.

## 필드별 작성 규칙

| 필드                  | 규칙                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------- |
| `genericSummary`      | 선택한 구조가 무엇인지 한 문장으로 설명한다. species/family 범위를 과장하지 않는다.                      |
| `actualName`          | 공식 영문 구조명 또는 protein 이름을 쓴다. 첫 등장에 공식명과 약어를 함께 둔다.                          |
| `role`                | “관여한다”만 반복하지 말고 결합·융합·포장·전달처럼 구체적인 작용을 쓴다.                                 |
| `location`            | `외피 표면`, `외피 바로 안쪽`, `capsid 내부`, `core 내부`, `tail 말단`처럼 관찰 가능한 상대 위치를 쓴다. |
| `relationships`       | 인접 구조와 연결·포함·둘러쌈 관계를 한두 문장으로 쓴다.                                                  |
| `modelRepresentation` | 현재 renderer의 형상, 반복, 묶음, 색·선택 그룹을 사실대로 쓴다.                                          |
| `simplification`      | 생략된 원자 구조, 실제 비율, 유연성, 당쇄, 비대칭 또는 개념 표식을 분명히 밝힌다.                        |
| `evidence`            | 아래 등급 정책을 따른다.                                                                                 |
| `sourceIds`           | 주장 범위를 직접 지지하는 등록 source만 연결한다. 최소 하나가 structural signature 근거와 맞아야 한다.   |

한 필드는 가능하면 120자 이내로 유지한다. 정보가 많으면 역할과 단순화 필드로 나누며, 3D 관찰을 밀어내지 않도록 보조 정보는 기존 `details` 안에 둔다.

## 근거 등급

- `observed`: PDB·EMDB·직접 구조 연구가 해당 구조와 주장 범위를 지지할 때 사용한다. 부분 구조를 전체 virion 좌표처럼 확대하지 않는다.
- `family-supported`: ICTV나 계열 구조 근거를 해당 species의 절차적 family model에 적용할 때 사용한다. 종별 차이를 임의로 만들지 않는다.
- `conceptual`: 방향 표식, 위치 관계, source에 직접 보이지 않는 genome coil처럼 관찰 보조용 표현에 사용한다.

설명이 `observed`이면 structural signature에도 `observed` 근거가 있어야 한다. source가 family morphology만 설명하면 종 특이 단백질 배열을 단정하지 않는다.

## 용어와 약어

| 용어                    | 사용 원칙                                                                              |
| ----------------------- | -------------------------------------------------------------------------------------- |
| capsid                  | 유전체를 감싸는 단백질 shell. UI의 모든 안쪽 층을 capsid라 부르지 않는다.              |
| nucleocapsid            | 핵산과 결합 단백질이 이룬 복합체. 단백질 shell만 뜻할 때는 capsid를 쓴다.              |
| matrix                  | 외피 바로 안쪽의 조립·형태 지지 단백질층. M protein과 혼동하지 않게 실제명을 병기한다. |
| tegument                | herpesvirus의 외피와 capsid 사이 비균일 단백질 영역. 균일 shell처럼 쓰지 않는다.       |
| envelope                | 지질 외피인지 단백질성 외곽인지 실제명을 명시한다.                                     |
| ribonucleoprotein (RNP) | 첫 등장에 영문명과 약어를 쓰고 이후 RNP로 통일한다.                                    |
| tail fiber              | 가늘고 긴 숙주 탐색·부착 섬유에 쓴다.                                                  |
| tailspike               | 짧고 굵은 수용체 결합 spike에 쓰며 tail fiber와 바꾸어 쓰지 않는다.                    |
| portal                  | capsid의 고유 꼭짓점에 있는 핵산 출입 축이다. neck 전체를 portal이라 부르지 않는다.    |

Protein 약어는 첫 등장에 `Hemagglutinin (HA)`, `Neuraminidase (NA)`, `membrane protein (M)`처럼 실제명과 함께 쓴다. 이후 같은 설명 안에서는 약어를 유지한다. 공식 구조명은 영문을 보존하고 역할과 위치는 자연스러운 한국어로 쓴다.

## 문체

- 사용자 문장은 `~해요`로 통일한다.
- 불필요한 피동형과 번역투를 줄인다.
- “관여해요”가 이어지면 `인식해요`, `감싸요`, `연결해요`, `통로를 만들어요`처럼 실제 작용으로 바꾼다.
- family 근거는 “family 수준에서 알려진 구조를 바탕으로 표시해요”, 개념 모델은 “현재 모델에서 개념적으로 단순화했어요”처럼 한계를 직접 말한다.
- 동일 family 설명의 재사용은 허용하지만, 근거 없는 species 차이를 추가하지 않는다.
