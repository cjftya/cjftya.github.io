# Jelly Oasis 운영·개발 안내

2026-11-16 실제 시간·날씨 연동 반영 기준이에요. 과거 단계별 보고서의 후보 URL·예산·통과 건수는 당시 기록이며 현재 기본값을 뜻하지 않아요. 전체 기록은 [문서 안내](../README.md)에서 찾아요.

## 실행과 현재 상태

`npm ci` 후 `npm run dev`로 `/projects/jelly-oasis/`를 열어요. 배포 빌드는 `npm run build`, 로컬 확인은 `npm run preview`예요. 독립 Vite 엔트리이며 `copy-legacy.mjs`가 빌드된 HTML을 원본으로 덮어쓰지 않도록 제외해요.

일반 화면에는 지형·세계수·유적·식생, 시간·날씨·하늘, 연못 수면과 후처리가 있어요. `main.ts`는 `pondOnly: true`, `water: true`, `waterfall: false`를 전달해요. 과거 폭포·수로 후보 기록만 보고 일반 화면에 다시 켜지 않아요.

초기 URL은 `startupOptions.ts`에서 한 번 해석해요. 검수 변형은 개발 모드 또는 `?debug`에서만 적용해요. 현재 기본값은 상세 절벽·유적·세계수·Crystal, 연못 v2 선택에 refined 미관 변형을 적용하는 경로예요. `?debug&pond=detail-v2`는 refined 이전 v2 비교용이고, `?debug&pond=blockout` / `?debug&pond=detail`은 이전 모델 비교용이에요. Crystal은 `?debug&crystal=blockout`으로 이전 모델과 비교해요. 일반 URL에서 이 모델 선택 쿼리로 기본값을 바꾸지 않아요.

## 수정할 위치

| 경로 (`src/jelly-oasis/` 기준)                                                 | 책임                                          |
| ------------------------------------------------------------------------------ | --------------------------------------------- |
| `main.ts`, `startupOptions.ts`, `app/`                                         | 장면 통합·생명주기, URL 옵션, 카메라·검수 API |
| `terrain/worldLayout.ts`, `terrain/heightfield.ts`, `terrain/createTerrain.ts` | 월드 설정, 결정적 높이 샘플, 지형 메시·색상   |
| `environment/timeOfDay.ts`, `environment/weather.ts`                           | 시간 계산, 날씨 프로필·전환                   |
| `environment/EnvironmentController.ts`                                         | 조명·하늘·안개·구름·비와 환경 자원 소유       |
| `landmark/`                                                                    | GLB 로딩, 접지·동선, 연못과 수면 자원         |
| `vegetation/`, `composition/`, `scenery/`, `meadow/`                           | 결정적 식생·풍경 배치와 인스턴싱              |

단일 시간·날씨 상태에서 조명·하늘·안개·강수가 함께 반응해요. 날씨는 `CLEAR`, `PARTLY_CLOUDY`, `OVERCAST`, `RAIN`, `MIST`, `DRIZZLE`, `SNOW`, `THUNDERSTORM`예요. 소나기·눈 소나기는 강수 계열로 표현하며 WMO 원래 종류는 연동 상태에 표시해요. 순수 계산과 Three.js 자원 소유를 구분하고, 큰 지형 형상과 반복 오브젝트는 생성 시 구성해요. 세부 기본값·예산은 현재 설정과 테스트를 확인해요. 초기 지형·환경 단계의 triangle/draw 수를 전체 장면의 현재 수치로 사용하지 않아요.

하늘의 거대 행성은 `environment/createSky.ts`에서 불규칙하게 휘어진 다중 크기의 구름 무늬와 청보라·진주빛 색면으로 그려요. 규칙적인 위도 줄무늬 대신 넓은 구름 형태를 사용하고, 낮·노을의 하늘색과 가장자리 대기 산란, 안개·악천후 감쇠로 배경에 섞어요. 행성과 두 달의 명암은 지상의 `sunDirection`을 각 천체의 좌표계로 변환해 계산해요. 기존 크기·위치·별 가림과 카메라 동작은 유지하며, 이미지 텍스처·메시·광원·후처리 패스를 추가하지 않아요. 행성 표면의 노이즈 계산은 늘어나므로 모바일 실기기 성능은 별도로 확인해요.

## 실제 시간·현재 위치 날씨

- 진입하면 브라우저 위치 권한을 요청해요. 고정 지역을 대신 사용하지 않아요.
  위치가 거부되거나 확인되지 않으면 기기 시간으로 표시하고, 날씨 연동 대기·권한 안내를 표시해요.
  환경 패널의 `현재 위치 다시 확인`으로 다시 요청할 수 있어요. HTTPS 또는 localhost가 필요해요.
- 허용된 좌표는 소수점 두 자리로 반올림해 Open-Meteo에 전달해요. 위치는 메모리에서만
  사용하며 저장하지 않아요. 페이지를 다시 열거나 버튼을 누르면 위치를 다시 확인해요.
- `RealitySync.ts`는 15분마다 현재 날씨를 가져오고, API의 IANA 시간대로 현지 시각을
  표시해요. 해외 날짜 경계·서머타임은 `Intl.DateTimeFormat`이 처리해요. 첫 응답 전이나
  통신 실패 때는 기기 시각을 사용해요. 시계는 매초 실제 시각을 다시 읽어 탭 복귀 시 바로 따라잡아요.
- `realTime.ts`는 NOAA 근사식으로 UTC·위경도·날짜에서 태양 고도와 방위를 계산해요.
  계절과 남북반구에 맞게 낮·밤을 바꾸며 기존 판타지 하늘색·두 달·행성을 유지해요.
  `lightingTimeOfDay`는 기존 수면·발광 효과에도 같은 낮·밤을 전달하는 팔레트용 값이에요.
- `liveWeather.ts`는 WMO 날씨 코드, 구름량, 강수·강설량과 풍속·풍향·돌풍을 검증해요.
  데이터는 관측소의 실측이 아닌 기상 모델 기반 현재 조건이에요. 30초 동안 부드럽게 전환해요.
  눈은 제한된 point 입자, 뇌우는 기존 장면에 부드러운 조명 펄스로 표현해요. 적설·우박 모델은 추가하지 않아요.
  움직임 줄이기 설정에서는 번개 펄스를 끄고 강수 애니메이션을 정지해요.
- 동시에 한 요청만 허용하고 12초 제한, 실패 시 1분 뒤 재시도해요. 최대 2시간은 마지막
  날씨를 유지하며 그 이후에는 기본 맑음으로 전환하고 오래된 자료임을 안내해요.
  숨겨진 탭에서는 새 조회를 하지 않고, dispose 후 늦은 응답과 위치 콜백을 무시해요.
- 시간 슬라이더와 수동 날씨 선택은 해당 실제 연동을 해제해요. `현지 실제 시간`과
  `현재 위치 날씨`를 다시 체크하면 복귀해요. 랜덤 날씨는 실제 날씨와 동시에 실행하지 않아요.
- 무료 비상업용 Open-Meteo API를 사용하며 API 키는 없어요. 환경 패널에 출처 링크와
  위치 전달 안내를 표시해요. [공식 문서](https://open-meteo.com/en/docs),
  [서비스 조건](https://open-meteo.com/en/terms),
  [태양 계산 근거](https://gml.noaa.gov/grad/solcalc/solareqns.PDF)를 참고해요.

검증 시작점은 `tests/jelly-oasis-reality-sync.test.ts`예요. 코드 매핑·오류 응답·신선도,
해외 시간대·DST·계절·극지, 권한 거부·재시도·요청 중복·수동 전환·해제를 검사해요.
브라우저의 실제 위치 제공은 사용자 기기와 권한 설정에 따라 별도로 확인해야 해요.

## 초기 로딩 중 응답성

2026-11-16부터 초기 랜드마크 구성은 `loading/loadingSteps.ts`의 협력 실행기로 진행해요.
약 6ms의 CPU 작업을 수행하면 `scheduler.yield()` 또는 타이머로 실행을 양보해 입력과
렌더링이 진행될 기회를 줘요. 시간 예산은 체크포인트에서 확인하므로 개별 Three.js
호출·드라이버 작업·GC까지 6ms 이하로 제한한다는 뜻은 아니에요.

- 호수 윤곽·지형 가공·외곽 클리핑, 접지·장애물 계산, 세계수·정원 구성,
  식생 배치·인스턴스와 바람 바인딩, 물 마스크·격자 생성을 작은 단위로 나눠요.
- 기존 동기 API는 같은 generator를 끝까지 실행하므로 검수용 `place()`·재배치와
  복구 동작을 보존해요. 초기 생성만 브라우저의 다른 작업과 번갈아 실행해요.
- 완성된 랜드마크를 장면에 붙이기 전에 색상 셰이더 준비를 소규모 묶음으로 진행해요.
  실제 조명·안개를 사용하며 인스턴스/색상 속성 변형을 구분해요. 그림자 셰이더,
  GPU 버퍼 업로드와 드라이버 동기화는 첫 렌더링에서 남을 수 있어요.
- 영구 페이지 이탈 시 다음 체크포인트에서 구성을 중단하고 부분 자원을 정리해요.
  BFCache 복귀를 위한 페이지 보존은 유지해요. RAF만 기다리지 않아 숨겨진 탭에서
  초기화 Promise가 무한 대기하지 않아요.
- `?debug`의 `window.__oasisLandmark.snapshot().loading`으로 모델 다운로드·해석
  `assetsMs`, 구성 `construction`(CPU 합계·대기 포함 경과·최대 작업 구간·단계별 값),
  셰이더 준비 `shaderWarmupMs`, 첫 랜드마크 렌더 호출 `firstFrameMs`를 구분해요.
  `firstFrameMs`는 CPU에서 측정한 렌더 호출 시간이며 GPU 완료·화면 표시 지연 측정은 아니에요.

전체 418개 테스트, lint, TypeScript 및 배포 빌드를 통과했어요. 추가 테스트는
입력 작업의 실행 기회, 지형·경계·물 마스크 결과 보존, 부분 생성 취소·자원 해제,
셰이더 준비 중 취소를 검사해요. 현재 미리보기 브라우저는 WebGL을 사용할 수 없어
실제 장면·모바일 터치·프레임 지연 개선량은 실기기에서 확인해야 해요.

## 보존할 동작

- seed와 지형 샘플링, 모델 앵커·접지·동선, 연못 경계와 실제 자산 경로를 유지해요.
- 반복 오브젝트는 공유 geometry/material과 인스턴싱을 활용하고 프레임마다 지형이나 자원을 재생성하지 않아요.
- 정적 상태의 불필요한 draw를 줄이되 바람·수면처럼 별도로 진행하는 애니메이션을 고려해요. 환경 시간 정지와 모든 애니메이션 정지는 같은 의미가 아니에요.
- hidden page, BFCache 복귀, resize, WebGL 손실·복구, 영구 이탈 시 dispose를 함께 확인해요.
- GPGPU 수면과 CPU fallback을 보존해요. 후보 선택·UI의 과거 설명만으로 현재 자원 경로나 기본 수면을 변경하지 않아요.
- physics·navmesh나 범용 게임 엔진을 정리 작업에 추가하지 않아요.

## 검증

```bash
npm run lint
npm run format:check
npm test
npm run build
```

전체 포맷 검사는 기존 보고서 등의 차이로 실패할 수 있어요. 변경한 문서만 먼저 검사하고 무관한 파일을 일괄 포맷하지 않아요. Uriel 공식 데이터 조회는 네트워크 작업이므로 일반 정리에 필요하지 않으며 `data:update`를 실행하지 않아요.

브라우저 검수는 스크립트별 환경 변수와 전제 조건을 먼저 읽어요. 모든 스크립트가 최신 기본 장면과 호환되는 것은 아니에요.

## 과거 캡처 보관

바이트가 동일한 과거 캡처 321개는 대표 파일로 통합했어요. [정리 기록](../archive/README.md#이전-정리-이력)과 [원래 경로 → 대표 경로 대응표](artifact-deduplication.json)를 확인해요. 과거 QA JSON·manifest는 당시 기록을 유지하므로 이미지 경로가 대응표의 `removed`에 있으면 `retained`를 사용해요. 새 캡처는 기존 QA 도구로 원래 출력 경로에 재생성할 수 있어요. 새 미디어는 기본적으로 Git에서 무시하며, 검토 후 보존할 자료만 `git add -f -- <경로>`로 추가해요. 대표 파일을 이동하거나 변경할 때는 대응표·문서 링크를 함께 수정하고 `npm run archive:check`를 실행해요.

### 실제 시간·날씨 연동 검증 기록 (2026-11-16)

전체 409개 테스트와 빌드가 통과했고, 이후 움직임 줄이기 전환 중 실제 시간 유지
회귀 테스트를 추가했어요. 현재 환경의 미리보기 브라우저는 WebGL이 비활성화되어
장면 렌더링·눈·번개 화면 검증은 실행하지 못했어요. 실제 기기에서 위치 허용 후
현지 시각·날씨 표시, 낮·밤·강수 표현을 확인해야 해요.
